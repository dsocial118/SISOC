# Migracion a Django 5.2 LTS

## Alcance

- Se actualiza el framework de Django 4.2.27 a Django 5.2.16 LTS.
- Se reemplaza el argumento deprecado `CheckConstraint.check` por
  `CheckConstraint.condition` en los modelos de `core` y `users`.
- Las senales de dashboard se registran al cargar la aplicacion sin consultar
  la base de datos durante `AppConfig.ready()`.

## Datos y migraciones

El cambio de argumentos de las restricciones conserva el SQL y los nombres de
las constraints existentes. `makemigrations --check --dry-run` no detecta
cambios; no se agregan ni reescriben migraciones historicas.

## Validacion

- Resolucion completa de `requirements.txt` y build Docker con Django 5.2.16.
- `python manage.py check` y arranque MySQL con `RuntimeWarning` como error.
- Suite completa SQLite con cobertura minima de CI.
- Suite `mysql_compat` contra MySQL real.
- `makemigrations --check --dry-run` contra MySQL.
- `check --deploy`, validacion OpenAPI y `collectstatic` en perfil `prd`.

## Despliegue y rollback

El merge a `development` habilita la validacion funcional en QA. Ante una
regresion atribuible al framework, el rollback consiste en revertir este cambio
y restaurar el pin `Django==4.2.27`; las dependencias preparadas en el PR previo
siguen siendo compatibles con ambas lineas.
